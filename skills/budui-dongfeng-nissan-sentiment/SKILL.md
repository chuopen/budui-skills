# 东风日产公域舆情监控

## 意图

为东风日产舆情分析人员提供**手动触发**的公域声音采集能力：

- **输入**：车型名称（可选，缺省为热门车型）、时间范围（可选，缺省近7天）、关注维度（可选）
- **输出**：结构化 JSON 文件，包含每条声音的平台来源、原文摘要、情感标签、关键话题等字段
- **消费者**：下游报告生成技能（如 consulting-analysis 或自定义 HTML 报告技能）

## 工作流程

### 第一步：确认采集参数

从用户提示词中提取以下参数，缺失时使用默认值：

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| car_model | 否 | 热门车型列表 | 东风日产在售车型，如"天籁""轩逸""逍客""探陆"等 |
| time_range | 否 | 近7天 | 搜索时间窗口，支持"近3天""近30天""本月"等自然语言 |
| focus_topics | 否 | 空 | 关注维度，如"油耗""空间""售后""智驾"等 |
| max_results | 否 | 30 | 单车型最大采集条数 |

若用户未指定车型且未说"热门"，主动询问目标车型。一次最多采集 3 个车型，超出时分批执行。

### 第二步：多平台搜索采集

对每个车型，使用 WebSearch 工具按以下策略搜索：

1. **搜索关键词构造**：`"{车型名} {平台名} {用户评价/口碑/吐槽/体验}"` + 可选 `{focus_topics}`
2. **平台覆盖优先级**：汽车之家 > 懂车帝 > 小红书 > 微博 > 抖音 > 百度贴吧 > 知乎 > 其他
3. **每个平台至少执行 1 次搜索**，结果不足时补充通用搜索 `"{车型名} 车主真实评价"`
4. **去重**：同一内容跨平台转载时保留最早或最完整的版本

搜索时使用当前可用 WebSearch 工具，不依赖特定 API 密钥或爬虫服务。

### 第三步：信息提取与结构化

对每条搜索结果，由大模型提取以下字段（详见 [references/output-schema.md](references/output-schema.md)）：

```json
{
  "id": "唯一标识",
  "car_model": "车型名称",
  "platform": "来源平台",
  "url": "原文链接",
  "publish_date": "发布日期(YYYY-MM-DD)",
  "author_type": "车主|媒体|KOL|普通用户|未知",
  "content_summary": "100字以内原文摘要",
  "sentiment": "positive|neutral|negative",
  "sentiment_score": 0.0-1.0,
  "key_topics": ["话题标签数组"],
  "raw_text_snippet": "原文片段(200字以内)"
}
```

**情感判定规则**：
- `positive`：明确表扬、推荐、满意表达
- `negative`：明确批评、投诉、后悔、故障反馈
- `neutral`：客观描述、参数对比、无明确倾向的提问或转述
- `sentiment_score`：0.0（极负面）到 1.0（极正面），0.5 为中性基准

### 第四步：输出与交付

1. 将所有条目写入 JSON 文件：`sentiment_{车型}_{日期}.json`
2. 文件顶层结构：

```json
{
  "metadata": {
    "car_model": "车型",
    "time_range": "采集时间范围",
    "collected_at": "采集时间(ISO8601)",
    "total_count": 0,
    "sentiment_distribution": {"positive": 0, "neutral": 0, "negative": 0},
    "platform_coverage": ["已覆盖平台列表"]
  },
  "items": []
}
```

3. 向用户返回文件路径和简要统计摘要（总数、情感分布、覆盖平台数）
4. 提示用户可将该文件传递给报告生成技能

### 第五步：量化数据增强（可选）

当用户要求"数据支撑""量化数据""硬数据"或采集结果仅有文本评价缺少数据时，自动执行量化增强。也可由用户主动触发。

在 `metadata.quantitative_data` 中补充以下三类数据：

#### 5.1 口碑分项评分（koubei_scores）

通过 WebSearch 搜索 `"{车型} 汽车之家 口碑评分"` `"{车型} 懂车帝 评分"` `"{车型} 百车故障数"` 获取：

- **综合评分**：汽车之家、懂车帝、易车三平台车主口碑评分
- **百车故障数**：汽车之家质量评价（2-12个月新车质量研究）
- **高频好评标签**：TOP5 好评关键词及提及次数
- **高频差评标签**：TOP3 差评关键词及提及次数
- **净推荐值**：如有第三方调研数据则收录
- **竞品口碑**：同步采集2-3款同价位竞品的上述指标用于横向对比

#### 5.2 销量与排名（sales_trend）

通过 WebSearch 搜索 `"{车型} 月度销量 2026"` `"{车型} 零售量 排名"` 获取：

- **月度零售/终端量**：最近6-12个月逐月数据
- **排名信息**：最新月份的整体排名、细分市场排名、占厂商份额
- **趋势总结**：环比变化、峰值/谷值、连续增长/下滑月数
- **归因分析**：基于公开信息的销量波动原因（如新车红利、召回事件、竞品分流等）

#### 5.3 竞品横向对比（competitor_comparison）

基于5.1中已采集的竞品数据，构建多维度对比矩阵：

- **对比维度**：综合评分(各平台)、百车故障数、核心好评、核心差评
- **N7竞争优势**：基于数据的优势总结
- **N7竞争劣势**：基于数据的劣势总结

所有量化数据来源须在 `metadata.notes` 中标注具体平台和采集时间。字段结构详见 [references/output-schema.md](references/output-schema.md)。

### 第六步：Excel 导出（可选）

当用户要求"Excel""表格""方便查看"时，基于同一 JSON 数据源生成 `.xlsx` 文件。

使用 Python openpyxl 库生成包含以下 Sheet 的 Excel 文件：

| Sheet | 内容 | 格式要求 |
|-------|------|----------|
| 舆情明细 | items 全量数据 | 情感标签列用绿/黄/红底色区分；支持自动筛选 |
| 口碑评分 | N7评分 + 标签词频 + 竞品口碑表 | 分区展示，带子标题 |
| 销量趋势 | 月度销量表 + 排名 + 趋势总结 | 含环比变化列 |
| 竞品对比 | 横向对比矩阵 + 优劣势总结 | 优势绿底、劣势红底 |

通用格式要求：
- 表头深蓝底白字加粗
- 所有数据单元格带细边框
- 长文本列启用自动换行
- 列宽适配内容
- 文件名：`sentiment_{车型}_{日期}.xlsx`

## 注意事项

- WebSearch 结果为公开网页摘要，不代表完整原文；提取时注明"基于搜索结果摘要"
- 情感标签由大模型判定，非人工标注，存在主观偏差风险
- 单次采集受搜索引擎索引和返回限制，不保证穷尽所有声音
- 不存储、不缓存历史采集结果，每次均为实时搜索
- 不涉及任何账号登录、Cookie 或私有 API 调用

## 排除项

- 不做私域数据采集（企微、APP 内评论、客服工单）
- 不做实时流式监控或告警推送
- 竞品对比仅作为量化增强的附属模块，不做独立深度竞品分析报告
- 销量数据仅用于舆情背景支撑，不做销售预测或经营决策建议
- 不替代专业舆情监测平台（如清博、新榜）的深度分析能力
- Excel 导出仅为数据可视化辅助，不替代正式 BI 报表系统
