# 交付 Excel 格式规范（与 2026 年 2 月春节交付件逐格对齐）

## 明细 Sheet（每个节日日一个）

```
行1  A1:H1 合并   「节日专项伙食补贴报销电子发票使用明细表（七大组）」 苹方-简18 加粗 居中  行高39
行2  A2:C2 合并   「部门（章）：XX」 苹方-简11 左对齐                          行高18
行3  表头  A序号 B发票号码 C开票日期 D发票金额 E实际报销金额 F使用部门 G使用人 H所属节日（YYYY.M.D）
             苹方-简12 居中 细边框                                        行高21.75
行4… 数据行（序号补足20行，空行也要边框）                          行高21
     合计行  B「合计」 D=SUM(D4:D23) E=SUM(E4:E23)                 行高21
     考勤行  A:H 合并「X月X日，以上员工的当班天数、日期与考勤相符」苹方-简12 居中 行高17.6
     签名行  A:B 合并「制表人：」 D:E 合并「部门负责人：」 G「分管领导：」
```

列宽：A 4.9 / B 24.2 / C 11.2 / D 9.1 / E 13.8 / F 11.9 / G 38.0 / H 25.9 / I 6.0

单元格规则：
- 全部苹方-简；数据 11 居中，F 使用部门 10 居中，G 使用人 8 左对齐
- B 发票号码：文本格式 `@`（20 位数字）
- 「备用」/「待确认」G 格：苹方-简8 红色 FFFF0000；「可加X人」用富文本（姓名黑、可加X人红）
- I 列辅助公式 `=INT((D行-E行)/50)`，居中、**无边框**、打印区域外
- 批注挂在 G 格：字典外姓名、待确认票

## 合计 Sheet

行1 直接表头（序号/发票号码/开票日期/发票金额/实际报销金额/使用部门/使用人/所属节日），无标题行、无总计行。
数据按天分组，**序号每天从 1 重新计数**。列宽 A 6.3 / B 24.8 / C 18.9 / D 9.1 / E 13.8 / F 11.9 / G 29.5 / H 25.9 / I 9.6。

## 每人汇总 Sheet（独立 xlsx，版式对齐 2026 春节交付样例）

独立文件，两个 Sheet：`餐补汇总表（无餐车）`（名字按交付范围用 --summary-sheet 改）+ 内嵌`工资号`字典 Sheet（A 姓名 / B 工资号 / C 职名，供 VLOOKUP，**隐藏**——仅作数据源，不进视图和打印）。

```
行1  A1:G1 合并   「2026年春节专项伙食补贴汇总表（七大组）」 宋体20 无加粗 居中  行高32.25
行2  A2           「部门（公章）：XX」 宋体12 左对齐                          行高23.25
行3  表头  A序号 B部  门 C工资号 D姓 名 E职 名 F当班天数 G金额
                  宋体12 居中 细边框                                         行高24.95
行4… 数据行（宋体12 居中 细边框；D 姓名宋体11、C 工资号 Times New Roman 12；
     A 序号 numfmt '0_ '）                                        行高18.95
     数据区补足到 35 行（--summary-rows，空行带边框和序号）
     总计行  B「总 计」 F=SUM(F4:F最后一行) G=SUM(G4:G最后一行)
     考勤行  A「1月15-23日，以上员工的当班天数、日期与考勤相符」宋体12 居中
     签名行  A 单元格「制表人：…部门负责人：…分管领导：」左对齐
```

列宽：A 5.375 / B 14.01 / C 15.625 / D 14.01 / E、F 默认 / G 14.01。

内容规则：
- 人员 = 有效票（非备用/待确认/抬头异常、金额已知）里出现过的姓名；**按工资号字典顺序排**，字典外人员垫底且 C/E 留空（报告人工核实）
- 当班天数 = 该人出现的开票日期**去重数**（同人同天冲突只算 1 天，冲突已在报告列出）
- C 工资号 `=VLOOKUP(D行,工资号!A:B,2,0)`；G 金额 `=F行*50`；SUM 范围盖住补足空行（便于手工补人）
- 打印：竖向 A4、打印区 `A1:G签名行`，页边距左右 0.24 / 上下 0.2（窄边距才能把 41 行压进一页，勿用默认 Letter/0.7 边距——会溢出第 2 页）；整表宋体、无加粗、无填充色

## 打印

每个 Sheet：`print_area = A1:H最后一行`（排除 I 列）、fitToWidth=1 fitToHeight=0、A4、页边距左右 0.71 / 上下 0.75。

## 文件名人名解析（scripts/build_detail_workbook.py 中的 parse_names）

支持日期写法：`2026年9月25日`、`9月25日`、`9月 25 日`、`10 月 7`（可缺「日」）、`9.25`、`10.1`、`（10.2）`、`10.7号`（日期后可带「号」）；
剔除：公司名、20 位发票号、`备用/加餐/伙食补贴/多50元/50元/50/元`、`(2)` 重名后缀、下划线、片段两端非中文噪音（`925贺天镛`、`耿楠楠d`）、粘在人名前的班组前缀（`动78班范光付`→`范光付`）；
分隔：`、 ， , 空格 . 。 和 （）`；2–4 位纯中文片段即人名（不依赖字典，字典只做批注）。
**连写人名**：≥5 字纯中文片段按工资号字典拆分，每段 2–4 字且**全部命中字典才接受**（如`李唐清刘军刘坚`→3 人）；**4 字及以下不拆**——与合法复姓/四字姓名无法区分；拆不开的片段写进报告提示人工核对，否则会静默漏人、实报少算（2026-10-11 教训：「动78班谢宇轩，远凯鑫」曾只解析出远凯鑫）。
日期/公司名等清洗要**先于**人名切分；务必用 basename 解析（目录前缀的 `/` 会粘坏第一个名字）。

## PDF 字段提取要点（数电票版式，pymupdf words + 坐标）

- 发票号：`\d{20}`；开票日期：`\d{4}年\d{1,2}月\d{1,2}日`
- 价税合计：找「（小写）」标签，同行 y±6 右侧的 `¥` 金额（标签与数字 y 差约 3.5，容差 3 会漏）
- 购买方：y 90–145、x<300 区域的名称与税号；销售方在 x>300
- 开票人姓名在 y≈372，不要误当使用人或备注
- 备注区一般为空；读取时以「注」标签与「开票人」行之间、x>40 为界

## 已知坑

- LibreOffice 命令行转换找不到 macOS 系统中文字体（含 ~/Library/Fonts 下的 ttc）：把单个 .ttf（如 Arial Unicode）拷进 `/Applications/LibreOffice.app/Contents/Resources/fonts/truetype/` 即可
- 挂载卷上的 PDF 偶发瞬时锁：重试 3 次
- 沙箱/字体缺失会让渲染只有数字没有汉字——是渲染环境问题，不是文件问题；先查 PDF 内嵌字体再怀疑文件
- 读旧缓存 JSON 会导致“新发票消失”：构建前确认数据源时间戳
- **单日票数超过 20 张**：合计行 SUM 范围必须跟随实际行数（曾固定 `D4:D23`，第 21 行起不进合计，2026-10-11 已修，勿改回固定值）
- **扫描/拍照件无文本层**：parse_pdf 提不出任何字段，脚本记入报告「无法解析的 PDF」节（不静默丢票）；用 fitz 渲染 PNG 人工目检原件，核对结论以「人工补记」写进报告（2026-10-11 曾有一票即个人抬头拍照件，退回重开）
