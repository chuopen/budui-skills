# budui-伙食补贴发票报销

节假日（中秋、国庆、春节等）伙食补贴发票 PDF → 交付级报销明细 Excel + 每人汇总表 + 问题报告。所有业务规则来自用户确认，改动前先问。

## 何时用 / 何时不用

**用**：给定一个按日期分文件夹的发票 PDF 目录 + 工资号字典 xlsx，要产出「每个节日日一个明细 Sheet + 最后一个合计 Sheet」的交付 Excel、**每人一份的伙食补贴汇总表**（部门/工资号/职名/当班天数/金额）和问题清单。

**不用**：没有发票 PDF、只凭考勤数据做工资号表；发票重开流程；网页工具 `index.html` 的维护。

## 输入

1. `--invoice-dir`：发票根目录（子文件夹按日期组织，允许错位——最终按 PDF 开票日期归组）
2. `--dict-xlsx`：工资号字典（「工资号」sheet：A 姓名、B 工资号、C 职名，296 人）

## 用法

```bash
python3 scripts/build_detail_workbook.py \
  --invoice-dir "<发票根目录>" \
  --dict-xlsx "<工资号字典.xlsx>" \
  --atten-note "2026.9.25=9月25-27日" --atten-note "2026.10.1=10月1-2日" \
  --out "<明细.xlsx>" --report "<报告.md>" \
  --summary-out "<每人汇总表.xlsx>" --summary-title "2026年春节专项伙食补贴汇总表（七大组）" \
  --summary-sheet "餐补汇总表（无餐车）" --summary-note "2月17-22日"
```

汇总表四个 `--summary-*` 参数每次交付按实际节日/范围改（不传则：文件名=标题、Sheet 名「餐补汇总表」、考勤说明按有效票日期范围自动生成）。

依赖：`pymupdf`、`openpyxl`。交付前把工作簿（明细和汇总表都要）**各复制一份副本**用 LibreOffice 重算校验（`xlsx.py recalc`，0 公式错误才算过——汇总表的 VLOOKUP/SUM 也在这一步验）并渲染 PNG 逐页目检。⚠️ recalc 保存时会把解析不到的字体（苹方-简/宋体在本机 LO 都会）统一替换成 Arial Unicode MS 烙进文件——**重算只做校验，交付的一定是脚本直出的原始文件**（脚本已设 fullCalcOnLoad，打开时自动重算，合计显示不受影响）。

## 业务规则（用户确认过，不要改）

- **每人每天最多 50 元；使用人人数上不封顶**，只要发票金额够。实报金额 = min(人数×50, 发票金额)
- 发票金额 − 实报 ≥ 50 时，在使用人后加红字「可加X人」（富文本，姓名黑色、可加X人红色），I 列辅助公式 `=INT((D-E)/50)` 打印区域外
- **按发票号查重**：同一发票号出现在多个 PDF 时，取文件名人名多的那张（同数保留先出现的），保留/剔除明细写进报告查重结果节；文件名内嵌 20 位号码与 PDF 提取值不一致要报告
- **购买方校验**：名称 + 税号必须匹配（默认 广深铁路股份有限公司广九客运段 / 91440101721187389L），不匹配的票不进任何 Sheet，单独写进报告提示退回重开
- **人名核对**：解析自文件名（字典只用于批注，不决定人数）。字典外姓名照常输出 + 单元格批注（可能是新员工）；字典里同名同工资号是重复录入，**不作为问题处理**
- 文件名解析不出人名的非备用票 → 红字「待确认」、实报留空、加批注，等用户确认
- 「备用」票：排在当天明细末尾，实报 0，所属节日留空，红字「备用」
- 同一人同一天出现多张有效票要报告（每人每天只能报一次）
- **金额不足必须报异常（2026-10-12 用户确认）**：人数 ≥2 且 发票金额 < 人数×50 时按人均 50 元报不平（如 81 元写 2 人，人均只有 40.5），不得默默按封顶计入——明细表实报留空、使用人后红字「金额不足」、批注说明差多少；合计 Sheet 同样标红；汇总表涉及人员姓名标红加批注、该天不计入当班天数；报告单独列节。1 人票金额 < 50 属正常（人均 ≤50 即可），不算异常。确认处理（按人数核定/退回重开）后**重跑脚本**
- **每人汇总表每次交付必须多出这一份**：当班天数 = 该人在有效票（非备用/待确认/抬头异常）中出现的开票日期去重数，金额 = 天数×50；**人员按金额从高到低排**（2026-10-12 用户确认），同金额保持字典序、字典外按首次出现顺延——字典外人员不做垫底特殊处理，金额高照样排前（工资号、职名留空，报告里人工补）；备用/待确认/抬头异常票不计入，待确认票确认后**重跑脚本**再交付

## 交付格式（详见 references/format-spec.md）

- Sheet 名 = 开票日期（`2026.9.25`），按日期数值排序；明细 Sheet 数 + 1 个「合计」Sheet
- 每个明细表：标题 → 部门（章）：XX → 表头（序号/发票号码/开票日期/发票金额/实际报销金额/使用部门/使用人/所属节日（日期））→ 数据行（序号补足 20）→ SUM 合计行 → 考勤说明行 → 制表人/部门负责人/分管领导签名行
- 开票日期写发票上的日期（`2026.9.25` 式）；使用部门「广深动车队」；所属节日「X月X日伙食补贴」
- 合计 Sheet：无标题行，按天分组，序号每天从 1 重新计数
- 发票号码列文本格式（20 位）；A–H 数据区细边框；苹方-简（标题 18 加粗、表头 12、数据 11、使用部门 10、使用人 8）
- 打印设置：fitToWidth=1，打印区 A1:H（排除 I 列）
- **每人汇总表**（独立 xlsx）：Sheet 名如「餐补汇总表（无餐车）」+ 内嵌「工资号」字典 Sheet；列序 号/部门/工资号/姓名/职名/当班天数/金额，A–G 细边框，宋体无加粗（标题 20、表头/数据 12、姓名 11、工资号 Times New Roman）；工资号列 `=VLOOKUP(姓名,工资号!A:B,2,0)`、金额 `=F*50`；数据区补足 35 行，总计行 SUM、考勤说明行、签名行；竖向打印 A1:G。详见 references/format-spec.md

## 报告必须包含

待确认票（文件名无使用人）、**金额不足票**（人数≥2 且发票金额<人数×50，未计入，需确认处理）、抬头异常票（未计入）、字典外姓名（标注输出）、文件夹与开票日期不符（已按开票日期归组）、查重结果（同号票保留/剔除哪张）、同人同天多张有效票冲突、**汇总表对账**（人数/人天/总计 vs 明细实报合计，差额 = 可加X人补贴 +、发票封顶少算 −、同人同天重复计 +）、**无法解析的 PDF**（扫描/拍照件等提取不到字段的票，未计入，需人工对照原件处理——不得静默跳过）、**连写人名拆不开的片段**（已解析部分照常输出，提示人工核对是否漏人）、各 Sheet 张数与金额汇总。交付 Excel 时**必须**同时给这份报告——用户靠它确认需要人工处理的票。
