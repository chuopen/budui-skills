# 发布判定与恢复策略

## “同一个项目”的证据

强证据：项目的 `origin` 是 GitHub URL，或用户明确给出 `OWNER/REPO`。弱证据：目录名、README 标题、仓库描述或搜索结果相似。只有强证据可直接更新；弱证据只能成为待确认候选。

## 发布前阻断项

- 工作目录不在用户指定项目范围内，或混有不相关内容
- 发现 `.env`、私钥、凭据、令牌、Cookie、个人数据、私有客户材料，或未确认可公开的资产
- 目标仓库、owner、默认分支或可见性不明确
- 远端分支存在未合并差异，且用户未选择整合方案
- 远端非快进更新需要强推

## 可恢复性

普通提交推送：可通过新提交回滚；不会自动执行回滚。新建空仓库：可保留或由用户明确要求删除。仓库改为公开、强推、删除历史和删除仓库不属于默认能力，需另行明确授权。

## 检查标准

预检必须报告：身份、路径、当前分支、remote、工作区状态、候选仓库、文件范围、敏感文件模式、README、LICENSE、`.gitignore` 和可运行的项目检查。没有项目定义的测试命令时应标记 `missing evidence`，不要虚构通过结果。
