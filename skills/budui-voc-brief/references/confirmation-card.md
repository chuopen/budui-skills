# 口径确认卡片规范

**卡片的目的不是汇报，而是在口径存在实质歧义时让用户快速决定。**

写卡片时要问：**当前是否还有会改变统计口径、结论或交付内容的未决项？** 有就问清楚；没有才执行。一个回复不足以消除歧义时，可继续下一轮确认。

---

## 1. 根本问题：不要写审计报告

反面案例（真实产出，用户原话"我根本没有心情看完"）：

```
【口径确认】座椅 VOC（28,939条 / 07-01~08-08 / 39天）
① 四级含"座椅"915条，但其中673条是正面口碑（座椅舒适性好），纯标签不可用。
   正文含"座椅"1,690条（负面441）。
② 容错候选：疑似错拼"坐椅"5、"椅座"2；现象词命中：异响155、按摩237、
   通风185、加热120、调节92、记忆41、塌陷35、放倒29。
③ 定稿口径请选：A 全主题(推荐)＝...1,330条，负面441，外溢415(服务类213)
   ｜B 缺陷视角→486条｜C 纯标签→915条(不建议)。
④ 基线：目标N7(14,893) vs 基线NX8(14,046)，基数接近可比。
⑤ 周期、主口径时间范围未确认，却擅自按周报执行。
⑥ 本环境无Chrome/Edge，PNG长图与PDF暂无法渲染，先出Excel+海报HTML。
```

**病在哪：**

| 病症 | 具体表现 | 后果 |
|---|---|---|
| 决策数超标 | 用户真正要拍板的只有 1 件（口径），卡片却摆出 6 个区块 | 认知负荷错配 |
| 备选方案污染 | 给了 A/B/C 三个口径，还要用户自己判断业务目的 | 把该我做的方案设计推给用户 |
| 数字无结论 | `673条正面口碑`、`异响155、按摩237、通风185…` | 用户无法判断对错，只能选择信或不信 |
| 平铺无主次 | 8 个现象词数字并列，没告诉用户该看哪个 | 信息量增加，信息价值为零 |
| 环境问题甩锅 | `无Chrome/Edge，PNG/PDF无法渲染` | 我的工具问题，变成你的决策负担 |
| 过程日志泄漏 | 对话里混进 `Now I have enough evidence`、`执行1次脚本`、`863.7k` | 污染界面，干扰阅读 |

## 2. 七条硬约束

1. **只问实质决策**——报告类型与主口径时间范围、多车型范围、问题边界、需确认相关词；不问环境和可可靠推断的信息。
2. **同轮集中问已知未决项**——用户不必来回补充；答案仍不完整或发现新歧义时，再开下一轮。
3. **每个选项可直接回答**——候选尽量不超过 4 个；自定义日期必须明确起止日期。
4. **数字必须带人话结论**——不写"673 条正面"，写"**七成在夸舒适**，当问题分析会把好评算成投诉"。
5. **不铺开过程细节**——容错、错拼、字段识别内部消化完，只报"已处理"。
6. **环境问题自己扛**——无浏览器、跨度不足、字段缺失，自己降级 + 产出中标注。
7. **不出现运行日志**——工具调用、token、脚本过程一律不进卡片。

## 3. 标准模板

```
【口径确认】<主题>

问题：这 N 条要怎么读？
  A. <候选1 一句话>   ← <什么情况下选它>
  B. <候选2 一句话>   ← <什么情况下选它>

我建议 <A 或 B>，因为 <一句业务理由>。
请回复你的选择；若选自定义时间，请给出起止日期。

<基线车型>｜<周期>｜<数据范围>｜视觉 <当前预设>——其余默认已定，有异议再说。
```

至少交代：主题 / 当前未决项 / 可选项（带选择场景）/ 建议与理由 / 已确认的范围。不要把环境问题或运行过程写进卡片。

## 4. 写法对照表

| ❌ 报告式 | ✅ 决策式 |
|---|---|
| `四级含"座椅"915条，其中673条是正面口碑（座椅舒适性好），纯标签不可用` | `标签里 915 条提到座椅，但七成是在夸舒适，直接拿来分析会把好评算成投诉` |
| `容错候选：疑似错拼"坐椅"5、"椅座"2` | `7 条把座椅打成了"坐椅/椅座"，已并入` |

| `③ 定稿口径请选：A…｜B…｜C…` | `问题：这 N 条要怎么读？A… B…` |
| `④ 基线：目标N7(14,893) vs 基线NX8(14,046)，基数接近可比` | 底部一行：`基线 NX8｜周报｜07-01~08-08` |
| `⑥ 本环境无Chrome/Edge，PNG长图与PDF暂无法渲染` | 不提。脚本自行降级，产出时标注 |

## 5. 何时执行

只要存在会实质改变结论的未决项就发送卡片并等待用户选择；不能用虚构的倒计时替代用户决策。报告类型未说明时，必须先问周报／月报／专项简报；专项还必须确认时间范围。不存在实质歧义时，按推荐口径直接执行，并将口径与扩展词记录在产出中。

## 6. 两种主题形态，两种问法

`profile.py` 会区分主题是否含现象词，卡片跟着分两类：

### 形态 A · 对象 + 现象（如"发动机异响""门把手收不回"）

```
【口径确认】<对象><现象>

问题：用哪个层级？
  A. 四级「发动机」+ 含"异响" —— 1 条，太窄
  B. 三级「发动机系统」+ 含"异响" —— 16 条

我建议 B，A 只捕到 1 条说明标签粒度不匹配。
请回复 A 或 B；若报告类型与时间范围尚未确认，也请一并说明。

基线 NX8｜周报｜07-01~08-08——其余默认已定。
```

### 形态 B · 只有对象、没有现象（如"座椅""轮胎""空调"）

**这是最容易出错的形态。** 脚本不得猜一个现象（如把"座椅"猜成"座椅异响"），必须走对象全覆盖，**并报出正负面占比**：

```
【口径确认】座椅

问题：这 838 条怎么读？其中 90% 是好评（"座椅真舒服"）。
  A. 全量 838 条          ← 全貌：负面定位问题，正面看口碑资产
  B. 只看负面 87 条        ← 聚焦问题，不呈现口碑亮点

我建议 A，领导要看全貌：负面定位问题、正面看口碑资产、中性看咨询期望。
请回复 A 或 B；若报告类型与时间范围尚未确认，也请一并说明。

基线 NX8｜周报｜07-01~08-08——其余默认已定。
```

> **实测数据**：「座椅」标签命中 838 条，正面 751（90%）、负面 87（10%）。
> 若不报占比，用户根本不知道"838 条"意味着什么——这正是原卡片失败的核心原因。
> 全貌简报按数据自适应呈现：正面 ≥10 条自动出口碑亮点区块，正面不足自动聚焦负面，B 的效果等于强制隐藏亮点区。

## 7. 自查清单

卡片发出前逐条打勾，任一不通过就重写：

- [ ] 用户能否直接回答当前全部关键未决项？
- [ ] 正文是否只保留决策所需信息？
- [ ] 是否问清了全部会改变口径或结论的事项？
- [ ] 每个数字后面有没有"所以呢"的结论？
- [ ] **纯对象主题有没有报出正负面占比？建议是否默认全貌（A）？**
- [ ] 有没有把环境/工具问题写成待决策项？
- [ ] 有没有残留运行日志、token 数、脚本过程？
- [ ] 「我建议」后面有没有给出业务理由？
- [ ] 是否避免以超时、默认或猜测代替用户决策？
