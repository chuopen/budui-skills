# 模块规范 — 9 个分析模块的计算定义

本文件是 `scripts/analyze.py`、`scripts/insight.py` 的算法依据。修改算法前先改这里，再改脚本。

**模块分层**：m1～m8 是**事实层**（只做统计，不下判断）；**m9 是判断层**（从 m1～m8 的事实推导结论，不引入新数据）。

---

## 0. 数据接入与字段识别

数据为用户上传的 CSV。**列名不写死**，按以下规则模糊识别（按优先级取第一个命中）：

| 逻辑字段 | 识别规则 | 必需 |
|---|---|---|
| 日期 | 列名含「日期」 | 是 |
| 标签类型 | 含「标签类型」 | 否 |
| 一级/二级/三级/四级标签 | 含「一级标签」「二级标签」「三级标签」「四级标签」 | 二／三／四级至少一个必需 |
| 观点标签 | 含「观点」 | 是 |
| 情感 | 含「情感」 | 是 |
| 车型 | 精确等于「车型」；无则用「车系」 | 是 |
| 正文 | 优先「内容」，回退「声音片段」→「摘要」 | 是 |
| VIN | 含「VIN」 | 否 |
| 车型码 | 含「车型码」 | 否 |
| 大区 | 含「大区」 | 否 |
| 渠道 | 精确「渠道」 | 否 |
| 专营店 | 含「专营店」 | 否 |
| 唯一 ID | 含「模型声音ID」→「声音ID」 | 否 |

列名常带「（人工修正）」后缀，匹配时先去除括号内容再比较。

缺必需字段 → 中止并告知用户；缺可选字段 → 跳过对应模块，并在报告口径说明中标注「字段缺失，该模块未执行」。

## 1. 口径三层定义

| 口径 | 定义 | 用途 |
|---|---|---|
| **主口径** | 主关键词命中二级／三级／四级／观点标签的合并字段（如任一字段含「车门把手」）；现象条件仅匹配观点标签 | 规模、形态、趋势、集中度 |
| **车型范围** | 用户指定车型时，精确匹配“车型”列；未指定且多车型时先由用户选定某车型或全部车型 | 所有模块的分析分母与样本范围 |
| **主分析时间窗** | 用户确认的 `analysis_date_range.start/end`；未填写只允许表示用户明确选择“全部数据” | 首页声量、情感、形态、集中度、洞察、明细及渗透率分母 |
| **备选口径** | 主口径的相邻对象关键词或已确认的同义词 | 交叉验证主口径结论是否稳健 |
| **外溢口径** | 正文或标签命中关键词，**但四级标签不属于主口径** | 识别故障衍生的服务/流程问题 |

外溢口径**不是**「所有服务类声音」，必须带关键词条件，否则会混入无关声音。

### 1.1 主口径关键字提取字段（稳定性约束）

主口径的关键词走结构化分类字段的**二级 → 三级 → 四级 → 观点标签**合并字段（见 `common.scope_tag_blob`）；现象条件只走**观点标签**。车型只走“车型”列，三者不得混用。**不取** `内容 / 摘要 / 声音片段` 等自由文本字段。

理由：用户问「XX 相关」这类对象型主题时，若关键字同时匹配自由文本，会把咨询、补偿、
服务描述等噪声计入主口径，导致口径随标注松紧漂移、不可复现。固定到分类字段后，
同一份数据 + 同一主题永远得到同一主口径声量。

- 外溢口径（M6）与原文情报（M8）**仍保留自由文本扫描**——其定义本就是「正文或标签命中」「抽取原句」，
  与「主口径稳定」是两个独立诉求，不要一并改掉。
- `in_main_tagged`（标签口径对照 `robust_n`）维持「仅观点标签（vp）」口径，作为比 `tag_blob` 更严的交叉校验，
  用来观察主口径中有多少来自规范观点、多少来自 1~4 级标签。

## 2. 模块 1 · 数据体检

- 记录总数、日期范围、实际天数
- 唯一 ID 重复数（无 ID 字段时按整行去重）
- 关键字段缺失率（VIN / 门店 / 大区 / 车型码）
- 输出置信度提示：字段缺失率 > 30% 的维度，其相关结论标注「低置信」

## 3. 模块 2 · 规模与渗透率

```
主口径声量 N
渗透率(万分比) = N / 该车型全量声音 × 10000
负面率 = 主口径中「负面」条数 / N
正面率 = 主口径中「正面」条数 / N
中性率 = 主口径中「中性」条数 / N
```

**情感归一**：CSV 情感列取值不保证规范（可能有「正向」「好评」等变体），统一经 `common.emo_class()` 归一到 正面／中性／负面 三类后再计数；无法归一的值计入「其他」不参与三档率。

**正面口碑统计**（全貌呈现的数据源）：`vp_top_pos` = 主口径中正面行的观点标签 top5，条数与占比。观点主题归并（m4）也会独立统计正面主题覆盖率；它不与负面风险主题混算，不承担风险结论。

**渗透率必须用万分比**，不要用百分比（数值太小，如 1.01% 不如 101‱ 可读）。呈现时写中文「万分之 101」，不要用 ‱ 符号（小字号不可辨）。

## 4. 模块 3 · 基线对比

基线车型由用户在口径确认环节指定。

```
强度倍数 = (N目标 / 目标车型全量) ÷ (N基线 / 基线车型全量)
```

**前置检查**：两车型的全量声音基数差异 > 50% 时，倍数可比性下降，必须在结论旁标注「声量基数差异较大，倍数仅供参考」。

若数据中只有一个车型，或用户选择不对比，则跳过本模块并在报告中注明。

## 5. 模块 4 · 观点主题归并

按**正面／中性／负面三档分别**对观点标签做互斥主题归并，三档的规则、覆盖率、排行和结论均独立，严禁混算。负面主题用于风险图与风险结论；正面主题用于口碑解释；中性主题用于咨询与期望解释。

互斥归并按优先级顺序匹配，命中即停：

| 优先级 | 负面风险主题 | 匹配规则（作用于观点标签） |
|---|---|---|
| 1 | 异响类 | 异响｜响声｜噪音｜异音｜杂音｜咔｜哒｜嗡｜轰｜啸 |
| 2 | 卡滞类 | 卡｜滞｜不顺｜不回｜涩 |
| 3 | 开合失效类 | 打不开｜开不了｜关不上｜关不严｜无法关闭｜无法打开 |
| 4 | 失灵类 | 失灵｜失效｜没反应｜无反应｜不工作｜不管用 |
| 5 | 损坏类 | 坏｜断｜裂｜碎｜损｜变形｜凹陷 |
| 6 | 脱落类 | 脱落｜掉落｜掉了｜松脱｜脱开 |
| 7 | 外观类 | 划伤｜划痕｜掉漆｜色差｜毛刺｜磨损 |
| 8 | 间隙类 | 缝隙｜间隙｜不平｜不齐｜错位｜翘 |
| 9 | 性能类 | 慢｜弱｜不足｜达不到｜偏差 |
| 10 | 设计抱怨类 | 不满｜建议优化｜希望｜设计｜形式 |

规则可由 `theme_rules: {正面: [], 中性: [], 负面: []}` 覆盖；旧 `shape_rules` 仅兼容为负面规则。未命中记录**不得以“其他”作为业务主题**出现在简报、排行或环图中。任一情感档覆盖率低于 85% 时，不对该档展示主题图或主题集中结论；负面档还必须明确展示“已归并／未覆盖”数量和 3–5 个待补规则高频观点，作为规则审计提示而非业务分类。

另输出 `vp_emo`：观点标签 × 情感交叉计数（top30 观点标签的三档分布），供 Excel ③ 表展示每个观点的正负构成。

## 6. 模块 5 · 趋势（周期归一） 

| 周期 | 聚合粒度 | 主区间 | 趋势窗口 |
|---|---|---|---|
| 日报 | 按日 | 最近 1 天 | 近 14 天 |
| 周报 | 按周 | 最近 1 完整周 | 近 8 周 |
| 月报 | 按月 | 最近 1 完整月 | 近 6 月 |

- **必须做均值归一**：`日均 = 该周期声量 / 该周期实际天数`。首尾周期通常不完整，直接用绝对量会误判趋势。
- 同时计算 `占全量比(万分比) = 周期声量 / 周期全量声音 × 10000`，用于剥离「整体声量涨跌」的干扰。
- 数据覆盖不足窗口时收窄到实际区间，**并在口径说明中标注**（如「数据仅 39 天，月报趋势仅 2 个点」）。
- 当前趋势只算主口径总量，不分情感；分情感趋势线（正面/负面走势分离）为规划中的增强项，实现前须先在本节登记。
- 趋势可使用主分析时间窗以外的同主题历史记录作参照；它们**不得**进入首页主指标或洞察分母。周标签显示 `MM/DD–MM/DD`，跨年时显示 `YYYY/MM/DD–YYYY/MM/DD`，不得使用 `W27` 一类周序号。

## 7. 模块 6 · 售后外溢

```
直命中外溢集 = 同车型、同主分析时间窗、未归入主口径，且正文或结构化标签命中 `spill_keywords`（未配置时继承已确认的主关键词）
关联扩展集 = 同车型、同主分析时间窗、未归入主口径，且命中用户明确确认的 `spill_related_terms`
服务外溢集 = 直命中外溢集 中 一级标签属于服务域（售后服务｜服务品质｜服务网络｜交付服务｜商城运营）
```

- **直命中是唯一可用于“外溢服务”、比值、排行和洞察的口径**；关联扩展必须单列，绝不混入。
- 每条外溢明细必须写出“外溢层级、命中词、来源定位”；直命中无命中词时立即中止执行。
- 按二级标签统计直命中服务侧分布 + 各类负面数；关联扩展只供人工复核。
- 输出「每 1 条主口径 ≈ 伴随 X 条直命中服务声音」的比值。

## 8. 模块 7 · 集中度

按可用字段逐个计算，字段缺失则跳过：

| 维度 | 算法 | 关注点 |
|---|---|---|
| 重复报修 | 按 VIN 分组计数，取 ≥2 次的 | 重复率 = 重复 VIN 数 / 有效 VIN 数 |
| 区域 | 按大区分组，剔除「无区域信息」 | 集中度 |
| 渠道 | 按渠道分组 | 入口分布 |
| 专营店 | 按**专营店名称**取 Top 10；不得使用专营店编码 | 单店异常 |

专营店名称字段缺失时跳过该维度；不得退回使用专营店编码。

## 9. 模块 8 · 原文情报

抽取含情报关键词的原句，去重后按关键词分组呈现。**关键词表按问题类型切换**：

| 类型 | 关键词 |
|---|---|
| 产品缺陷类（零部件/系统故障） | 改良品｜改进件｜通病｜召回｜统一方案｜批次｜投诉｜车质网｜懂车帝｜媒体｜曝光｜设计缺陷 |
| 权益流程类（积分/权益/退改） | 承诺｜未兑现｜推诿｜拖延｜没人管｜投诉｜12315｜客服｜系统故障 |

**原文处理规则**（两个必须）：

1. **截断**：≤132 字，且必须在 `。；！？` 处收尾，找不到标点才用 `…`。禁止句中硬切。
2. **去重**：按内容前 36 字（去空白）判重。同一次反馈可能在多条记录里出现，不去重会重复展示。

## 11. 模块 9 · 关键洞察与建议动作（判断层）

**定位**：把 m1～m8 的统计事实翻译成「怎么看 + 怎么办」。这是决策层唯一会读完的部分。

**核心纪律**：
1. **不引入新数据**。只看 m1～m8 已有的字段，不做二次统计、不调外部接口。
2. **结论必须可追溯**。每条洞察的 `evidence` 必须写清是哪几个数字支撑的，能回指到上游模块。
3. **禁止无依据推断**。数据支撑不到的方向，宁可不报，也不要写「可能是……」。

### 11.1 阈值表（改这里即调敏感度）

阈值集中在 `scripts/insight.py` 顶部 `TH` 字典：

| 键 | 默认值 | 含义 | 触发后 |
|---|---|---|---|
| `neg_rate_systemic` | 90.0 | 负面率 ≥ 此值 | 系统性缺陷（red / P0） |
| `neg_rate_high` | 70.0 | 负面率 ≥ 此值 | 负面集中（amber / P1） |
| `multiple_model` | 5.0 | 基线倍数 ≥ 此值 | 车型特有问题（red / P0） |
| `multiple_notable` | 3.0 | 基线倍数 ≥ 此值 | 高于基线（amber / P1） |
| `spill_ratio` | 0.50 | 外溢/主口径 ≥ 此值 | 服务外溢（amber / P1） |
| `shape_dominant` | 60.0 | 单一负面主题占负面声量 ≥ 此值 | 负面主题高度集中（red / P0） |
| `shape_min_coverage` | 85.0 | 主题规则覆盖率最低阈值 | 未达阈值不输出主题图或主题集中结论 |
| `repeat_rate` | 20.0 | VIN 重复率 ≥ 此值 | 重复报修（red / P0） |
| `trend_up` | 1.30 | 末周/均值 ≥ 此值 | 趋势上升（amber / P1） |
| `trend_down` | 0.70 | 末周/均值 ≤ 此值 | 趋势回落（info / P2） |
| `trend_min_points` | 4 | 趋势点少于 4 个 | 不做趋势判断 |
| `small_sample` | 30 | 主口径 < 此值 | 样本不足（amber / P1），且一句话总结追加提示 |
| `concentration_top` | 40.0 | 头部单项占比 ≥ 此值 | 集中风险（amber / P2） |
| `pos_rate_good` | 60.0 | 正面率 ≥ 此值 | 口碑优势（good / P1） |
| `pos_shape_dominant` | 50.0 | 正面中首位观点标签占比 ≥ 此值 | 正面集中·客户在夸什么（good / P1） |
| `neutral_signal_rate` | 30.0 | 中性率 ≥ 此值 | 中性咨询信号（info / P2） |
| `pos_present_min` | 10 | 正面条数 < 此值 | 不出正面判据，海报不渲染口碑亮点区块 |

### 11.2 判据清单（15 条）

| # | 类型 | 触发条件 | 性质 | 优先级 |
|---|---|---|---|---|
| 1 | 样本不足 | `n < small_sample` | amber | P1 |
| 2 | 系统性缺陷 | `负面率 ≥ 90` | red | P0 |
| 3 | 负面集中 | `70 ≤ 负面率 < 90` | amber | P1 |
| 4 | 车型特有问题 | `倍数 ≥ 5` | red | P0 |
| 5 | 高于基线 | `3 ≤ 倍数 < 5` | amber | P1 |
| 6 | 负面主题高度集中 | `首位已归并负面主题占负面 ≥ 60` 且覆盖率 ≥ 85% | red | P0 |
| 7 | 服务外溢 | `外溢/主口径 ≥ 0.5` | amber | P1 |
| 8 | 重复报修 | VIN 重复率 ≥ 20% | red | P0 |
| 9 | 趋势上升 / 趋势回落 | 末点/均值 ≥ 1.3 或 ≤ 0.7 | amber / info | P1 / P2 |
| 10 | 峰值异常 | 峰值 ≥ 均值×2 且 ≥ 5 条 | info | P2 |
| 11 | 集中度风险 | 单一维度首项占比 ≥ 40 | amber | P2 |
| 12 | 口碑优势 | `正面率 ≥ 60` 且正面 ≥ pos_present_min | good | P1 |
| 14 | 正面集中 | 正面首位观点标签占比 ≥ 50 | good | P1 |
| 15 | 中性咨询信号 | `中性率 ≥ 30` | info | P2 |

判据 4/5、10 内部互斥（if/elif）。集中度只在**最集中的一个维度**上报，避免堆砌。判据 13/14 在正面条数 < `pos_present_min` 时跳过（样本太少的正面不构成口碑结论）。

### 11.3 输出结构

每条洞察：

| 字段 | 说明 |
|---|---|
| `kind` | 洞察类型（上表「类型」列） |
| `level` | `red` / `amber` / `info` / `good`，决定卡片配色（good=口碑亮点，绿色） |
| `title` | **一句话结论，必须含关键数字** |
| `evidence` | 支撑事实列表，可回指上游模块（最多渲染 2 条） |
| `root` | 待验证方向（业务解释，非统计描述，不构成因果结论） |
| `action` | 建议动作（可执行、有对象） |
| `priority` | `P0` / `P1` / `P2` |
| `owner` | 建议牵头方 |

另输出：
- `actions`：动作清单，按 P0→P1→P2 排序，字段 `{priority, action, owner, from}`
- `summary`：一句话总结，**分区取 top**——存在 red/amber 风险洞察时取优先级最高、最严重的一条；风险洞察全空而存在 good 洞察时取 good 头条（口碑导向简报的标题位）；全部为空时写「未触发风险判据，建议维持常规观察」；样本不足时追加「（样本量小，方向可信、幅度慎用）」

### 11.4 呈现位置

| 载体 | 位置 |
|---|---|
| Excel 明细 | `⓪ 关键洞察` 工作表（**放在最前**，决策层先看）+ 动作清单段 |
| 海报 HTML | 区块 ③ 决策摘要、⑧ 关键洞察卡（最多 6 条）、⑨ 建议动作（最多 6 条） |
| 终端 | `【关键洞察】` 段，🔴/🟠/⚪ + 优先级 + 根因 + 动作 |

### 11.5 边界

| 情况 | 处理 |
|---|---|
| m3 为 None（无基线） | 跳过判据 4/5，其余照常 |
| 无 VIN 字段 | 跳过判据 9 |
| 趋势点 < 4 | 跳过判据 10/11 |
| 正面条数 < `pos_present_min`（10） | 跳过判据 13/14，海报不渲染口碑亮点区块，口径说明标注「正面 N 条，占比 x%，未达呈现阈值」 |
| 洞察为空 | 输出「未触发风险判据」而非空白 |
| 洞察 > 6 条 | 海报只渲染前 6 条（若存在 good 洞察，截断时保底保留 1 条），其余指向 Excel |

## 12. 降级与边界
