# budui-voc-brief — VOC 专项简报

把一整批 VOC 客户声音数据里的**某一个具体主题**，做成能支撑决策的全貌简报：负面定位问题、正面看口碑资产、中性看咨询期望。

## 何时使用 / 何时不用

**使用**：用户给出一批数据 + 一个主题，要一份结论性报告。

| 触发样例 | 说明 |
|---|---|
| 分析一下轮胎爆胎问题 | 部件 + 现象（问题导向） |
| 帮我做个发动机异响的简报 | 系统 + 现象（问题导向） |
| 积分未到账的数据做一下 | 权益流程类 |
| 座椅口碑怎么样 / 看看座椅反馈 | 纯对象主题（口碑导向） |

**不用**（转交其他技能）：

| 场景 | 转交 |
|---|---|
| 单条/少量 VOC 判产品还是服务 | `voc-router` |
| 单条 VOC 拆成七要素 | `voc-viewpoint-split` |
| 单条 VOC 归入产品/服务分类树 | `voc-product-classify` / `voc-service-classify` |
| 分类标准的建立、评审、改版 | `voc-classification-standard` / `budui-voc-classifier` / `budui-voc-definer` |
| 标注质量与自定义观点审计 | `voc-custom-viewpoint-audit` |

## 四段流程（口径、分析与外发不得混为一步）

### Step 0 · 意图与词汇归一

先判断用户要的是“某主题的 VOC 专项简报”，再从自然语言中拆出**车型、对象、现象**。车型只走车型列；主关键词先归一后匹配二／三／四级标签与观点标签的合并字段；现象条件只匹配观点标签。

- 报告包装词不是现象：`声音`、`反馈`、`口碑`、`VOC` 只说明用户要分析客户声音，不能被当作“异响”等现象条件。
- 受控错别字与同义词可先归一，例如 `坐椅 → 座椅`。
- 语义更宽的相关词必须展示候选并确认，例如 `坐位 → 可能指座椅`，不能静默并入口径。

归一规则在 `assets/synonyms.json`；`profile.json.intent` 必须记录原词、归一词、来源及是否需要确认。

### Step 1 · 范围与口径发现

先确认数据文件与分析主题。用户未说明报告类型时，必须询问周报／月报／专项简报；专项简报还必须确认主口径时间范围（全部数据、今年至今、近 12 个月或自定义）。车型范围独立于标签口径：主题中出现车型时从“车型”列精确过滤；未出现且数据有多个车型时，必须先让用户选一个车型或“全部车型”。

| 输入 | 规则 |
|---|---|
| 数据文件 | 用户自主上传。**禁止猜测或扫描路径**；用户未给路径就问 |
| 分析主题 | 自然语言即可，允许错别字（容错在 profile 阶段处理） |
| 报告类型与时间范围 | 用户未说时必须确认周报／月报／专项；周报必须使用 `profile.json.recommended_time_windows.last_complete_week` 的起止日期，月报取最近完整自然月；专项必须选全部数据／今年至今／近 12 个月／自定义起止日期 |
| 目标车型 | 用户说出车型时直接从“车型”列精确过滤；未说且有多个有效车型时，列出车型及声量，让用户选 N6／NX8／全部车型 |
| 基线车型 | 用户选定具体目标车型后才可选；未指定则跳过基线对比 |
| 视觉主题（可选） | 不说则用 **琥珀晨曦**；可直接说「用深海蓝图」「蓝色简报」等，见下方预设表 |

然后执行：

```bash
python "<SKILL_DIR>/scripts/profile.py" \
  --data "<用户提供的数据文件>" \
  --query "<用户说的主题词，原样传入，不要预先纠错>" \
  --out "<工作目录>/reports/profile.json"
```

产出：意图识别结果（车型／对象／现象）+ 候选口径清单（二／三／四级标签与观点标签合并的主关键词、观点现象词、容错候选）+ 各候选的命中声量。

### Step 2 · 口径确认（直到所有实质歧义消除）

**目标：让用户一次看清当前已发现的关键未决项。** 可以分多轮确认；只要仍有会改变统计口径、结论或交付内容的歧义，就必须继续问清楚。

#### 硬性约束

| 约束 | 说明 |
|---|---|
| **问清全部实质决策** | 报告类型与时间范围、车型范围、问题边界、相关词等未决项必须确认；可分多轮 |
| **不超过 5 行正文** | 超了就是没提炼干净，重写 |
| **候选压缩到 2 个** | 最多 3 个（第三个只能是"不建议"的陪衬）。4 个以上说明我没想清楚 |
| **数字必须带人话结论** | 不能只给"673 条正面口碑"，要写"**七成在夸舒适**，当问题分析会把好评算成投诉" |
| **不铺开过程细节** | 容错、错拼、字段识别等已在内部处理完，只报一句"已处理" |
| **环境问题自己扛** | 无浏览器、数据跨度不足、字段缺失等，**自己降级并在产出中标注**，不得写成待用户决策项 |
| **不出现运行日志** | 工具调用、token 数、脚本执行过程一律不进卡片 |

#### 卡片模板（照此输出，不得扩写）

```
【口径确认】<主题>

问题：这 N 条要怎么读？
  A. <候选1 一句话>   ← <什么情况下选它>
  B. <候选2 一句话>   ← <什么情况下选它>

我建议 <A 或 B>，因为 <一句业务理由>。
请回复 A 或 B；没有实质歧义时，不发卡片，直接按推荐口径执行。

车型 <目标车型或全部>｜基线 <车型或不对比>｜<周期>｜<数据范围>｜视觉 <当前预设>（可直接换名）——其余默认已定，有异议再说。
```

#### 写法对照（反面 → 正面）

| ❌ 原来这么写 | ✅ 应该这么写 |
|---|---|
| `四级含"座椅"915条，其中673条是正面口碑（座椅舒适性好），纯标签不可用` | `标签里 915 条提到座椅，但**七成是在夸舒适**，直接拿来分析会把好评算成投诉` |
| `容错候选：疑似错拼"坐椅"5、"椅座"2` | `7 条把座椅打成了"坐椅/椅座"，已并入` |
| `现象词命中：异响155、按摩237、通风185、加热120…` | 不铺开。只报与主决策相关的 1～2 个 |
| `⑥ 本环境无Chrome/Edge，PNG长图与PDF暂无法渲染` | 不提。脚本自行降级，产出时在说明里标注 |

#### 执行规则

每轮集中询问当前已发现的全部关键未决项：报告类型与主口径时间范围、多车型范围、对象／现象边界、需确认的相关词。用户回答后若仍有实质歧义，或数据校验发现新的实质歧义，继续下一轮；不得以默认、超时或猜测替代用户决策。能由用户原话、数据字段和既定规则可靠推断的，不重复询问。视觉主题始终可直接在需求中指定，不作为确认卡的必答项。

### 口径冻结与影子审计

首次确认后，在任务工作目录保存 `reports/scope-baseline.v1.json`，冻结车型、对象词、现象词、扩展词、排除词及分析模式。后续相同主题运行必须复用该基线；只能更新时间窗和数据文件血缘，禁止静默扩词或重选标签。

但每次仍运行 `profile.py` 的候选发现作为**影子审计**：候选词不进入本期统计。候选新增声量达到 `≥5 条` 或 `≥主口径 10%` 时，提示用户“是否纳入并创建 scope-baseline.v2”；低于阈值只写入 Excel 口径审计页。只有用户明确同意或要求“修改口径／重新识别口径”时，才能创建新版本；新版本必须注明与 v1 不可直接同比。

口径确认（或按建议默认）后**不得再自行改动口径**。中途发现口径有问题，回到 Step 2 重新确认。

> 卡片结构、措辞规则与完整反例清单见 `references/confirmation-card.md`。


### Step 3 · 执行与产出

### 公域证据层（与私域并行）

公域检索默认关闭；只有用户明确说“加公域／看外部舆情／查公开投诉或媒体反馈”时才启用，并与私域分析并行。启用后**必须实际调用 WebSearch 工具，不能只写检索计划或凭记忆补写。** 公域检索继承已确认的车型、部件／主题；默认查中国大陆中文互联网，优先投诉平台、官方／媒体及汽车社区。只纳入可访问且带 URL、发布日期（可得时）和短摘录的页面；公域声量不得与私域相加，不得推断故障率。

首次检索应并行覆盖“车型 + 主题 + 投诉”“车型 + 主题 + 评测/媒体”“车型 + 主题 + 论坛/社区”，**不得把私域周报/月报的起止日期直接拼进关键词作为硬限制**。先找可核验证据，再按发布日期标为“同期”“近期背景”“历史背景”或“日期未知”；周报的同期不足时，展示近期/历史背景并明确其不属于当周。若没有可核验结果，必须用同义词或指定来源域名进行第二轮 WebSearch；两轮都无有效来源才可写“未检索到可核验公开证据”。WebSearch 工具调用失败、超时或不可用时，写“公域搜索未执行（原因）”，不得伪装成无结果。

将检索结果写入 `reports/public-evidence.json`，并在 `scope.json` 写入 `include_public: true` 和 `public_evidence_file`。文件必须记录 `search_runs`（每轮的查询词、执行时间、结果数、工具状态）；每条来源至少有 `title`、`url`、`source_type`、`published_at`、`time_bucket`、`excerpt`；无法核验时不写入。**检索完成并写入证据文件后，必须再运行 `analyze.py` 生成新的 `stats.json`，然后才能渲染四件套；禁止先生成 stats 再只渲染。** 海报先呈现私域，最末内容区固定为冷灰蓝底色的「公域舆情观察」；未启用时明确说明，并标注“外部链接证据，不计入私域统计”。海报不再展示数据体检与口径说明，完整口径与溯源保留在 Excel。

```bash
# 1) 跑 9 个分析模块（m1~m8 事实层 + m9 判断层）→ stats.json
python "<SKILL_DIR>/scripts/analyze.py" --scope "<工作目录>/reports/scope.json" --out "<工作目录>/reports/stats.json"

# 2) 渲染四件套
python "<SKILL_DIR>/scripts/render_excel.py"  --stats "<...>/stats.json" --out "<工作目录>/<主题>专项简报_明细.xlsx"
python "<SKILL_DIR>/scripts/render_poster.py" --stats "<...>/stats.json" --out "<工作目录>/<主题>专项简报.html" [--theme "深海蓝图"]
python "<SKILL_DIR>/scripts/render_image.py"  --html "<...>/简报.html"      --out "<工作目录>/<主题>专项简报"
```

`<主题>` 取用户原话里的对象/问题名（如"轮胎爆胎""座椅口碑"），用作文件名。

### UI 色彩预设

视觉主题只改变 HTML／PNG／PDF 的**品牌主色、浅色层、图表主序列和装饰图形**；负面红、正文深色、信息层级和数据结构不变。默认「琥珀晨曦」，不选不问；用户要换色时可在需求里直接说预设名、颜色或别名，也可在口径确认时和 A/B 一起回复，例如「A，深海蓝图」。

| 预设名 | 可直接说 | 适合场景 |
|---|---|---|
| **琥珀晨曦**（默认） | 橙色／暖橙 | 常规专项简报，温暖直接 |
| **深海蓝图** | 蓝色／科技蓝 | 工程质量、管理层复盘，冷静理性 |
| **青岚信号** | 青绿／绿色 | 服务体验、持续改善，清爽稳定 |
| **紫曜洞察** | 紫色 | 智能座舱、创新体验，有区分度 |
| **曜石极简** | 灰色／黑白 | 高层汇报、正式归档，低饱和克制 |

主题配置集中在 `assets/ui-themes.json`。运行时由 `scope.json` 的可选 `visual_theme` 字段写入 `stats.json`，`render_poster.py` 会识别预设 key、中文名或别名；单次渲染也可用 `--theme "深海蓝图"` 覆盖。查看列表：

```bash
python "<SKILL_DIR>/scripts/render_poster.py" --list-themes
```

> **四件套命名**：Excel 是 `<主题>专项简报_明细.xlsx`，其余三份是 `<主题>专项简报.{html,png,pdf}`。
> 推送脚本的命名候选同时兼容旧「问题分析」命名，传 `--files "<主题>专项简报"` 即可。

### Step 4 · 飞书推送（仅在用户明确要求时）

四件套落盘后默认本地交付。仅当用户明确说“推送飞书”或已配置可撤销的个人偏好时，才执行推送。

```bash
python "<SKILL_DIR>/scripts/render_push.py" \
  --stats "<工作目录>/reports/stats.json" \
  --files "<工作目录>/<主题>专项简报" \
  --to self
```

- `--to self` 优先从 dry-run 取当前身份；失败时回退读取本机配置。配置存在多个身份时停止并要求显式 `--to ou_xxx`，绝不猜测收件人。
- 发一条**摘要卡** + **4 份文件**。
- **摘要卡内容顺序（勿调）**：口径/条数/渗透率/**三档情感分布（正面/中性/负面）** → **■ 关键洞察（前 4 条）** → **■ 建议动作（前 3 条，含牵头方）** → 附件数。
  > 决策层可能只看这条消息。**关键洞察与建议动作必须出现在卡片里**，不能只丢文件让它自己翻 Excel。
- PNG 走图片通道（聊天内直接预览），Excel/HTML/PDF 走文件通道。

**发送通道**（脚本已内置，勿改）：

| 文件 | 通道 | 原因 |
|---|---|---|
| PNG | `--image` | 走文件通道则飞书不预览，只能下载 |
| Excel / HTML / PDF | `--file` | 非图片格式，图片通道会失败 |

推送失败**不阻断交付**——四件套已在本地落盘，脚本只打印结果并返回退出码。

| 退出码 | 含义 |
|---|---|
| 0 | 全部成功 |
| 4 | 部分失败（已发出部分） |
| 5 | 未找到 lark-cli |
| 6 | 未确定收件人 |

> 飞书推送的完整命令、路径陷阱与排错见 `references/push-feishu.md`。

## 呈现纪律（贯穿全流程）

**你是替用户做判断的人，不是把原始信息倒给用户的人。**

这条约束同时适用于确认卡片、进度播报、最终交付说明。

| 规则 | 说明 |
|---|---|
| **给结论，不给原料** | 「673 条是正面口碑」是原料；「七成在夸舒适，用纯标签会把好评算成投诉」才是结论 |
| **结论先行** | 每条播报第一句就是最重要的事，细节往后放。禁止先铺背景再说重点 |
| **不爆运行日志** | 工具调用次数、token 数、脚本执行过程、内部推理痕迹，一律不出现 |
| **问题自己扛** | 无浏览器、依赖缺失、数据跨度不足 → 自己降级 + 在产出中标注，**不写成待用户决策项** |
| **一屏原则** | 每轮只呈现当前已发现的关键未决项；简洁但不得遗漏会改变口径或结论的选择 |
| **进度播报极简** | 长任务只在关键节点报一句结果（如"分析完成，142 条，正在渲染"），不做过程直播 |

**自检**：发出的每一段话，问自己"用户看完需要做什么动作？"。如果答案是"看懂这些数字"，就该重写。

## 模块矩阵

所有报告均跑 8 个模块，但主分析区间必须由报告类型与时间范围决定；趋势区间只承担历史参照，不得反向扩大首页声量、负面率、形态、集中度及洞察的统计分母。

| 周期 | 聚合粒度 | 主分析区间 | 趋势窗口 | 对比方式 |
|---|---|---|---|---|
| 日报 | 按日 | 最近 1 天 | 近 14 天 | 前一日常 / 近 7 日均值 |
| 周报 | 按周 | 最近 1 完整自然周 | 近 8 周 | 上周 / 基线车型 |
| 月报 | 按月 | 最近 1 完整自然月 | 近 6 月 | 上月 / 基线车型 |
| 专项 | 按周或月（按跨度选） | 用户确认的时间范围 | 同粒度历史参照 | 所选区间 / 基线车型 |

数据覆盖不足窗口时，自动收窄到实际区间，**并在口径说明中标注**（例："数据仅 39 天，月报趋势图仅 2 个数据点"）。不得静默截断。

8 个模块与算法定义见 `references/module-spec.md`：

1. 数据体检 2. 规模与渗透率（含**三档情感分布与正面口碑排行**） 3. 基线对比 4. **三档独立**观点主题归并（附观点×情感交叉）
5. 趋势（周期归一） 6. 售后外溢 7. 集中度 8. 原文情报

“问题形态规则引擎”更名为**观点主题归并**：正面、 中性、负面各自按独立规则归并，绝不混算；负面主题用于风险判断，正面主题用于口碑解释，中性主题用于咨询解释。未命中记录不得以“其他”作为业务分类；任一档覆盖率低于 85% 时不展示该档主题图或集中结论，负面档还必须披露已归并／未覆盖数量和待补规则高频观点。

## 输入容错规则

用户输入允许有错别字、同义字、近义词。`profile.py` 先做意图归一，再按以下顺序扩展检索：

1. **原词精确匹配** → 二级／三级／四级／观点标签合并字段
2. **受控错别字／同义词归一** → 读 `assets/synonyms.json`，如 `坐椅 → 座椅`
3. **相关词候选** → 如 `坐位 → 可能指座椅`；必须明确确认，禁止静默纳入
4. **近义/近音扩展** → 拼音相似 + 编辑距离 ≤ 2 的候选（标注"疑似错拼"）
5. **前缀/子串** → 如"发动机"匹配"发动机系统"

同义词表随使用累积：用户每次确认的补充词，追加进 `assets/synonyms.json`。

**禁止**：把相关词候选偷偷算进口径。所有归一过程完整写入 `profile.json.intent` 与 `scope.json`；相关词候选必须由用户明确选择后才能纳入。

### 关键洞察与建议动作（m9 · 判断层）

**这是本技能最核心的交付价值**——用户拿到的不是一堆数字，而是「怎么看 + 怎么办」。

m1～m8 只做统计，**不下判断**；m9 从这 8 个模块的事实里推导结论。规则引擎在 `scripts/insight.py`，
阈值集中在文件顶部 `TH` 字典，**改阈值即调敏感度**。

**三条铁律**：

1. **不引入新数据**。只看 m1～m8 已有字段，不做二次统计、不调外部接口。
2. **结论必须可追溯**。每条洞察的 `evidence` 必须写清是哪几个数字支撑的，能回指上游模块。
3. **禁止无依据推断**。数据支撑不到的方向宁可不报，也不要写「可能是……」。

输出结构：每条洞察含 `kind`（类型）/ `level`（red·amber·info·**good**，决定配色，good=口碑亮点绿）/ `title`（一句话结论，**必须带数字**）/
`evidence`（支撑事实）/ `root`（待验证方向，不构成因果结论）/ `action`（建议动作）/ `priority`（P0·P1·P2）/ `owner`（牵头方）。

**15 类判据**（完整阈值表见 `references/module-spec.md` 第 11 节）：

| 类型 | 触发 | 优先级 |
|---|---|---|
| 样本不足 | 主口径 < 30 条 | P1 |
| 系统性缺陷 | 负面率 ≥ 90% | **P0** |
| 负面集中 | 负面率 70~90% | P1 |
| 车型特有问题 | 基线倍数 ≥ 5 | **P0** |
| 高于基线 | 基线倍数 3~5 | P1 |
| 负面主题高度集中 | 首位已归并负面主题占负面 ≥ 60%，且规则覆盖 ≥ 85% | **P0** |
| 服务外溢 | 外溢/主口径 ≥ 0.5 | P1 |
| 重复报修 | VIN 重复率 ≥ 20% | **P0** |
| 趋势上升 / 回落 | 末点/均值 ≥ 1.3 或 ≤ 0.7 | P1 / P2 |
| 峰值异常 | 峰值 ≥ 均值×2 且 ≥ 5 条 | P2 |
| 集中度风险 | 单维度首项占比 ≥ 40% | P2 |
| **口碑优势** | 正面率 ≥ 60% 且正面 ≥ 10 条 | P1（good） |
| **正面集中** | 正面首位观点占比 ≥ 50% | P1（good） |
| **中性咨询信号** | 中性率 ≥ 30% | P2 |

**呈现位置**（三处必须一致）：

| 载体 | 位置 |
|---|---|
| Excel | `⓪ 关键洞察` 表（**置顶**，决策层先看；good 行绿字标「亮点」）+ 动作清单段 |
| 海报 | 区块 ③ 决策摘要、⑧ 关键洞察卡（≤6 条，截断时保底保留 1 条 good）、⑨ 建议动作（≤6 条） |
| 飞书摘要卡 | **■ 关键洞察（前 4 条）+ ■ 建议动作（前 3 条，含牵头方）** |

> **海报与飞书都只放前几条**，超出部分指向 Excel。不要为了「完整」把 12 条全塞进去——那等于没做提炼。
> **洞察卡不重复渲染建议动作**（动作统一在动作区块呈现），否则同一句话出现两次。

### 缺件降级（不打断交付）

渲染或推送依赖缺失时**不报错中断**，按下列方式静默降级，并在交付说明里用一行小字标注实到件数：

| 缺失 | 行为 | 退出码 | 标注措辞 |
|---|---|---|---|
| 无 Chrome/Edge | 跳过 PNG/PDF，保留 Excel + HTML | `3` | 「本次交付 2 件：Excel、HTML；PNG/PDF 待装浏览器后补」 |
| 无 Pillow/numpy | 出 PNG 但不裁底部空白 | `0` | 「PNG 未裁剪」 |
| 无 openpyxl | 跳过 Excel，其余照出 | 由 render_excel 决定 | 「Excel 待补」 |
| 无 lark-cli | 跳过推送，四件套本地照出 | `5` | 「飞书推送跳过，文件已在本地」 |

**禁止**把这类环境问题写成待用户决策项放进确认卡片——用户要的是结论，不是我的依赖清单。

## 防坑清单

工程实现时必须遵守，均为真实踩过的坑：

1. **双轴图柱状数字放柱内**，白色粗体。放柱外会被折线点压住。
2. **万分号 ‱ 在小字号下不可辨**（渲染成 ‰）。一律写"万分之 X / 万分比"。
3. **周期趋势必须按日/周/月的日均归一**，首尾不完整周期直接用绝对量会误判趋势。
4. **客户原声按标点截断**（在 。；！？ 处收尾，retain ≤132 字）并**按内容前 36 字去重**。海报全篇最多显示 2 条代表性原声，售后外溢区只呈现结构图；完整引用留在 Excel，避免原声挤掉结论。
5. **窄栏条形图标签宽 79px + nowrap**，否则长标签折行破坏对齐。
6. **Windows 环境**：Python 用绝对路径调用；第三方包在隔离目录，脚本开头 `sys.path.insert`；脚本开头 `sys.stdout.reconfigure(encoding='utf-8')`。
7. **HTML→PNG/PDF 用 Chrome headless**：截图 `--headless=new --screenshot --force-device-scale-factor=2`，PDF 需配合 `@media print{@page{size:...}}` 才是单页长图；渲染后检测非背景行自动裁掉底部空白。
8. 外溢分析的口径是**正文命中关键词但标签未归入主口径**，不是简单的"所有服务类声音"。
9. **确认卡片只问会实质改变口径或结论的未决项**；同轮集中提问、可多轮确认，禁止用默认或超时替代未决选择。把审计数据倒给用户＝失职。反例见 `references/confirmation-card.md`。
10. **渲染脚本找不到浏览器时返回退出码 3 而不是崩溃**，保证 HTML 仍能交付。
11. **主题只含对象不含现象时（"座椅"/"轮胎"/"空调"），禁止猜一个现象把口径收窄**。必须走"对象全覆盖"口径，并同时报出正负面占比——因为这类词往往大部分是好评（实测「座椅」838 条里 90% 是正面），不报占比用户无法判断。判断依据：主题剥掉对象词后的残余 <2 字即视为无现象。
12. **纯对象主题的卡片必须给出"全貌 / 只看负面"二选一**（唯一该问的决策），**默认建议全貌**——领导要看的不只是问题，还有口碑资产与咨询期望。用户选"只看负面"时等于强制隐藏正面呈现，主口径本身不变。
13. **飞书 `--file`/`--image` 只接受相对路径**，绝对路径与 `..` 会被拒绝。必须 `cwd=文件目录` + 只传文件名。
14. **PNG 走 `--image`、其余走 `--file`**，通道不可互换：PNG 走文件通道则不预览，Excel/PDF 走图片通道会报错。
15. **四件套命名**（Excel 带 `_明细`，其余裸 stem），推送脚本要自动试三种命名候选，不要硬拼后缀。
16. **`doctor` 报 `user_identity: warn` 不影响推送**——那是 user token 过期，推送走 bot 身份 + 用户 open_id。
17. **m9 的 `evidence` 不得直接吐 Python 数据结构**（如 `{'负面': 136, '中性': 6}`）——必须转成人话「负面 136 / 中性 6」。用户看不懂 dict。
18. **m9 阈值改动只能改 `insight.py` 顶部 `TH` 字典**，禁止把数字硬编码进判据分支，否则无法统一调敏感度。
19. **海报/飞书的洞察条数要截断**（海报 ≤6、飞书 ≤4），超出指向 Excel。全量塞进去等于没提炼。海报截断时若存在 good 洞察须保底保留 1 条。
20. **洞察卡内不重复渲染建议动作**——动作只在动作区块出现一次，避免同一句话刷两遍。
21. **m6 的 `l2` 是三元组 `[名称, 条数, 占比]`**；`m7` 仅含大区／渠道／专营店名称的 `[名称, 条数]` 列表与 `vin` dict，已移除配置集中度。m9 里取值方式不同，写错就崩。
22. **正面呈现是数据驱动的，不要做成用户开关**：正面 ≥10 条（`pos_present_min`）才出口碑亮点区块、好评原声配额与正面判据；不足则自动聚焦负面并在口径说明标注一行。「轮胎爆胎」自动是问题简报，「座椅」自动是口碑简报，任何主题都不出现空亮点区。
23. **情感取值先归一再用**：`common.emo_class()` 把「正向」「好评」等变体归一到三档；m2 三档率、m9 正面判据、原声配额全部走归一值，不要拿 CSV 原始字面量做 `==` 比较（会静默漏计）。判序必须 负→正→中（「不满意」含「满意」）。
24. **渲染资源不完整必须中止**：`assets/ui-themes.json`、`assets/icon-map.json`、`assets/theme/hero-generic.svg`、`assets/svg/icon-generic.svg` 缺任一个都不得生成 HTML/PNG/PDF。运行环境必须整体复制 `assets/`，不能只复制 svg 子目录。
25. **数据必须可溯源**：所有主口径与外溢明细保留「声音ID（如有）+ CSV 行号」；原声不得重复选取同一文本；Excel 的「⑨ 数据溯源」记录源文件与口径 SHA-256。统计事实仅针对用户提供的源数据，待验证方向不得表述为因果事实。

## 完整命令链（照着跑）

```bash
P="<python绝对路径>"
S="<SKILL_DIR>/scripts"

# 1) 口径发现
"$P" "$S/profile.py" --data "<数据.csv>" --query "<用户原话>" --out reports/profile.json

# 2) 只有口径存在实质歧义时才等待用户选择；否则直接写推荐口径（结构见 module-spec.md 第 1 节）
#    必填: data_file / topic / period / main_scope{key:"tag_any",terms:[对象词],phenomenon}
#    常用选填: target_model / baseline_model / extra_terms / spill_keywords / spill_related_terms
#    时间窗: analysis_date_range: {start: "YYYY-MM-DD", end: "YYYY-MM-DD", label: "最近完整自然周"}
#    未填时间窗仅适用于用户明确选择“全部数据”；周/月/限定专项必须写入已确认起止日期。
#    周报不得自行按数据截止日倒推；必须取 profile 计算出的最近完整周一至周日。analyze.py 会拒绝不匹配的周报时间窗。
#    target_model 只来自“车型”列；主关键词匹配二/三/四级标签与观点标签合并字段；phenomenon 只匹配观点标签。
#    外溢：spill_keywords 是直命中词（未填则继承确认的主关键词）；spill_related_terms 必须由用户确认，且单列、不参与外溢服务指标。

# 3) 分析（scope.json 可选 visual_theme: "深海蓝图"）
"$P" "$S/analyze.py" --scope reports/scope.json --out reports/stats.json

# 4) 四件套
"$P" "$S/render_excel.py"  --stats reports/stats.json --out "<主题>专项简报_明细.xlsx"
"$P" "$S/render_poster.py" --stats reports/stats.json --out "<主题>专项简报.html" --theme "深海蓝图"
"$P" "$S/render_image.py" --html "<主题>专项简报.html" --out "<主题>专项简报"

# 5) 飞书推送（仅在用户明确要求时）
"$P" "$S/render_push.py" --stats reports/stats.json --files "<主题>专项简报" --to self
```

依赖：`openpyxl`（Excel）、`Pillow` + `numpy`（图片裁剪）、Chrome 或 Edge（渲染）、`lark-cli`（飞书推送）。
`common.add_site_packages()` 会自动探测隔离环境的 site-packages，无需硬编码路径。
